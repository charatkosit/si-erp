## Objective

สร้าง Compose baseline ที่ใช้ version จาก P0-04, แยก network/volume และตรวจ health ของทุก service ได้ โดยไม่ล่วงล้ำ application scaffolding ที่กำหนดไว้ใน P0-08

## In scope after blocker resolution

- Docker Compose v2 definition สำหรับ frontend, backend, PostgreSQL, Redis, MinIO และ reverse proxy `/api`
- การใช้ image pins และ platform-specific digest evidence จาก P0-04
- health checks, private service networking, persistent data volumes และ smoke-test/runbook ที่ไม่เก็บ secret

## Out of scope

- Package manifest/lockfile, dependency installation, Angular/NestJS routes/modules, production business feature, migration และ secret จริง
- การเปลี่ยน version baseline หรือ cache/queue server โดยไม่มี Change Request

## Current blocker

`B-P0-05-02`: MinIO ต้องมี root credential เพื่อเริ่ม service แต่ `.env.example` และ secret policy ถูกกำหนดให้เป็น P0-06. P0-05 จึงไม่อาจ commit ค่า credential หรือทำ `docker compose config/up` ผ่านด้วย environment ที่ยังไม่ถูกอนุมัติ.

## Decision required

The project owner approved deferring frontend/backend health acceptance to P0-08 on 2026-09-24 (D-018). The remaining decision is whether P0-05 may use explicitly documented, non-production development defaults for MinIO until P0-06 replaces them with `.env.example`, or whether MinIO runtime/health acceptance must defer to P0-06.

## Acceptance criteria after resolution

1. Compose uses P0-04 image pins and records resolved platform digests.
2. `frontend`, `backend`, `postgres`, `redis` and `minio` start according to the approved decision; reverse proxy routes `/api` correctly.
3. Every service health check required by the approved decision passes, and persistent volumes/network exposure follow SDD.
4. No real secret is committed; Compose, Dockerfiles and application changes stay within the approved lock.
5. `docker compose config`, health smoke tests, scope/secret checks, staged allowlist, Git commit/push and clean-tree evidence pass.
